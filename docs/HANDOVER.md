# التسليم لأكاديمية جديدة — نسخة بهويتها الكاملة

كل أكاديمية تحصل على **نسختها المستقلة**: مشروع Vercel خاص، وقاعدة بيانات
Supabase خاصة، واسم وشعار وألوان ومحتوى خاص بها. لا بيانات مشتركة بين النسخ.

---

## المسار الذاتي (المشتري ينفّذه بنفسه)

```
زر Deploy → Vercel ينسخ المستودع لحسابه
          → تكامل Supabase يُنشئ قاعدة ويحقن متغيّرات الاتصال
          → البناء يطبّق المخطط ويبذر القرآن تلقائياً (~دقيقة)
          → /setup: ينشئ حساب الإدارة الأول ببياناته
          → /admin/branding: الاسم والشعار والألوان والمحتوى
```

### ١. زر النشر

```
https://vercel.com/new/clone
  ?repository-url=https://github.com/im3lol/elhafazhacademy
  &integration-ids=<معرّف تكامل Supabase>
  &env=AUTH_SECRET
  &envDescription=سرّ%20توقيع%20الجلسات%20—%20أي%20نص%20عشوائي%20طويل
```

> **`integration-ids`**: يُنسخ من صفحة تكامل Supabase على Vercel Marketplace
> (يبدأ بـ `oac_`). إن لم يتوفّر، انشر بلا هذا المعامل ثم أضِف Supabase من
> تبويب **Storage** في مشروع Vercel — النتيجة نفسها، بخطوة إضافية.

`AUTH_SECRET` هو **الحقل اليدوي الوحيد**: التطبيق يرفض الإقلاع في الإنتاج بدونه
(الجلسات تصبح قابلة للتزوير بسرٍّ معروف). أي نص عشوائي ٣٢ حرفاً فأكثر يكفي.

### ٢. ماذا يحدث تلقائياً

| العنصر | كيف |
|---|---|
| سلسلة الاتصال | تكامل Supabase يحقن `POSTGRES_URL` و`POSTGRES_URL_NON_POOLING` — والتطبيق يقبل كليهما |
| المخطط (٣٥ جدولاً) | `scripts/setup.mjs` ضمن `npm run build` |
| الأدوار والصلاحيات والباقات | `db/init/02_seed.sql` |
| القرآن (٦٬٢٣٦ آية) والتخطيط (٨٣٬٦٦٥ كلمة) | نفس السكربت — يعمل وقت البناء حيث لا مهلة serverless |
| عنوان التطبيق | يُشتق من `VERCEL_PROJECT_PRODUCTION_URL` |

التهيئة **محروسة**: تعمل مرة واحدة فعلياً. كل نشرة تالية تنفّذ استعلامَين رخيصين ثم تنتهي.

### ٣. حساب الإدارة الأول

المشتري يفتح `/setup` وينشئ حسابه. الصفحة تُغلق نفسها بعد أول أدمن (تحوّل إلى
`/login`)، والإنشاء داخل معاملة بقفل استشاري فلا يتجاوزها طلبان متزامنان.

**لا توجد كلمة مرور افتراضية في المستودع** — المشتري وحده يعرف كلمته.

## قائمة تحقّق بعد التسليم

- [ ] `/admin/settings` ← بطاقة **قاعدة البيانات**: الجداول ٣٥، الكلمات ٨٣٬٦٦٥، الآيات ٦٬٢٣٦
- [ ] `/admin/branding` ← الاسم والشعار واللونان ومحتوى الصفحة الرئيسية
- [ ] `/admin/settings` ← بيانات التحويل، Resend (بدونه لا يصل استرجاع كلمة المرور)، Google Meet
- [ ] `node scripts/seed-showcase.mjs --clean` لمسح بيانات العرض قبل الاستخدام الحقيقي
- [ ] `CRON_SECRET` + المهمة الدورية (تذكيرات الحصص ودورة حياتها)
- [ ] نطاق مخصّص → اضبط `NEXT_PUBLIC_APP_URL` عليه

## التسليم اليدوي (إن نفّذتَه أنت)

```bash
DATABASE_URL="<سلسلة الاتصال>" npm run setup
```

ثم إمّا `/setup` من المتصفح، أو للطوارئ:

```bash
node scripts/seed-admin.mjs owner@academy.com "كلمة-مرور-قوية" "مدير الأكاديمية"
```
