# تشغيل نسختك — أكاديمية مستقلة بهويتها الكاملة

كل جهة تحصل على **نسختها المستقلة**: مستودع خاص، ومشروع Vercel خاص، وقاعدة بيانات
Supabase خاصة، واسم وشعار وألوان ومحتوى خاص بها. **لا بيانات مشتركة بين النسخ**،
ولا وصول لأي جهة إلى قاعدة جهة أخرى.

> **لا تعمل على المستودع الأصلي.** خذ **Fork** — الكتابة على مستودع واحد تعني أن أي
> دفعة من أي جهة تعيد نشر كل النسخ الأخرى. والـ Fork تحديداً (لا زر Deploy من Vercel)
> لأنه وحده يبقي صلة `upstream`، فزر **Sync fork** يسحب الإصلاحات بنقرة.

## المسار الكامل (تنفّذه الجهة بنفسها)

### ١. Fork للمستودع

من صفحة المستودع على GitHub: **Fork** → اختر حسابك. هذه نسختك؛ عدّل فيها ما تشاء.

### ٢. اربطه بـ Vercel

1. <https://vercel.com/new> → **Import Git Repository** → اختر الـ fork.
2. لا تضغط Deploy بعد — افتح **Environment Variables** وأضِف:

| المتغيّر | القيمة |
|---|---|
| `AUTH_SECRET` | نصّ عشوائي ٣٢ حرفاً فأكثر — `openssl rand -base64 32` |
| `CRON_SECRET` | نصّ عشوائي آخر (لحماية مسار المهام الدورية) |

3. **Deploy**. أول بناء **ينجح** لكن التطبيق لن يعمل بعد: لا قاعدة بيانات بعد،
   فيتخطّى `setup.mjs` التهيئة ويكمل البناء. الخطوة التالية تُكمل الناقص.

### ٣. أضِف قاعدة البيانات

في مشروع Vercel: تبويب **Storage** → **Supabase** → إنشاء قاعدة جديدة.
التكامل يحقن `POSTGRES_URL` و`POSTGRES_URL_NON_POOLING` تلقائياً، والتطبيق يقبل
كليهما — **لا ضبط يدوي لسلسلة الاتصال**.

ثم **Redeploy**. هذه المرّة يكتمل البناء ويهيّئ كل شيء:

| العنصر | كيف |
|---|---|
| المخطط (٣٥ جدولاً) | `scripts/setup.mjs` ضمن `npm run build` |
| الأدوار والصلاحيات والباقات وقوالب الإشعارات | `db/init/02_seed.sql` |
| القرآن (٦٬٢٣٦ آية) والتخطيط (٨٣٬٦٦٥ كلمة) | نفس السكربت — وقت البناء حيث لا مهلة serverless |
| عنوان التطبيق | يُشتق من `VERCEL_PROJECT_PRODUCTION_URL` |

التهيئة **محروسة وآمنة للتكرار**: كل نشرة تالية تنفّذ استعلامات رخيصة ثم تنتهي.
مدّة أول بناء ~دقيقة (بذر القرآن).

> **لا يوجد زر «أنشئ الجداول» داخل التطبيق، وهذا مقصود.** الجداول تُنشأ أثناء
> **البناء** حيث لا مهلة، لأن بذر ٨٣٬٦٦٥ كلمة لا يصلح داخل دالة serverless
> (سقف Hobby ١٠ ثوانٍ). وتغيير متغيّرات البيئة على Vercel لا يؤثّر على النشرة
> الشغّالة أصلاً — فربط القاعدة يستلزم نشرة جديدة، وهي نفسها التي تنشئ الجداول.
> إن فتحت الموقع قبل ربط القاعدة، توجّهك صفحة `/setup` بالخطوة الناقصة بالضبط.

### ٤. أول حساب إدارة

افتح `/setup` في متصفحك وأنشئ حسابك ببريدك وكلمة مرورك.

الصفحة **تُغلق نفسها** بعد أول أدمن (تحوّل إلى `/login`)، والإنشاء داخل معاملة بقفل
استشاري فلا يتجاوزها طلبان متزامنان. **لا توجد كلمة مرور افتراضية في المستودع.**

### ٥. هويتك ومحتواك

`/admin/branding` — الاسم، الشعار، اللونان، وكل نصوص الصفحة الرئيسية.

> ما لم تغيّره يظهر بالافتراضي «أكاديمية الحفظة». غيّر على الأقل: **الاسم، الاسم
> الكامل، السطر التعريفي، وصف الموقع (SEO)، وحقوق النشر في التذييل**.

### ٦. المهمّة الدورية (تذكيرات الحصص)

خطة Vercel المجانية تسمح بمهمّة يومية واحدة فقط، وهي لا تكفي — لذلك التذكيرات
تعتمد على GitHub Actions في مستودعك. من **Settings → Secrets and variables → Actions**:

| النوع | الاسم | القيمة |
|---|---|---|
| Variable | `APP_URL` | عنوان أكاديميتك، مثل `https://my-academy.vercel.app` (بلا `/` في آخره) |
| Secret | `CRON_SECRET` | **نفس** القيمة المضبوطة في متغيّرات Vercel |

ثم افتح تبويب **Actions** وفعّلها: GitHub يعطّل الجداول الزمنية في الـ Forks افتراضياً،
ويعطّلها ثانيةً بعد ٦٠ يوماً بلا نشاط على المستودع.

> بلا هذين الضبطين تفشل المهمّة برسالة واضحة بدل أن تعمل بصمت على عنوان خاطئ.

## قائمة تحقّق قبل الاستخدام الحقيقي

- [ ] `/admin/settings` ← بطاقة **قاعدة البيانات**: الجداول ٣٥، الآيات ٦٬٢٣٦، الكلمات ٨٣٬٦٦٥
- [ ] `/admin/branding` ← الاسم والشعار واللونان ومحتوى الرئيسية وحقوق التذييل
- [ ] `/admin/settings` ← بيانات التحويل، Resend (**بدونه لا يصل استرجاع كلمة المرور**)، Google Meet
- [ ] `/admin/account` ← بيانات الأدمن وبريد الدخول وكلمة المرور (متاحة لكل أدمن، بلا صلاحيات خاصة)
- [ ] `/admin/packages` ← الأسعار والعملة وعدد الحصص (الافتراضي ٤٥٠/٦٥٠/٩٥٠ ج.م)
- [ ] `APP_URL` + `CRON_SECRET` في إعدادات المستودع، وActions مفعّلة
- [ ] نطاق مخصّص → اضبط `NEXT_PUBLIC_APP_URL` عليه في Vercel
- [ ] نسخ احتياطي مجدول — [BACKUP.md](BACKUP.md)

> **قاعدتك تبدأ نظيفة.** البناء يبذر القرآن والأدوار والباقات الافتراضية فقط — لا
> طلاب ولا معلمين ولا حصص تجريبية. (سكربتات `seed-demo` و`seed-showcase` للتطوير
> المحلي وحده ولا تعمل على Vercel.) وكل خطوات هذا الدليل تُنفَّذ من المتصفّح — لا
> تحتاج طرفية إطلاقاً.

## كيف أسحب التحديثات لاحقاً

الإصلاحات والمزايا الجديدة تصل من المستودع الأصلي:

1. من صفحة الـ fork على GitHub: زر **Sync fork** → **Update branch**.
2. Vercel يلتقط الدفعة وينشر تلقائياً.
3. `scripts/setup.mjs` يطبّق أثناء البناء ما استجدّ على القاعدة (صلاحيات، قوالب
   إشعارات، أعمدة، فهارس) — كل جمله idempotent فلا يضرّ تكرارها.

**قبل أي سحب:** خذ نسخة احتياطية — [BACKUP.md](BACKUP.md).

**تجنّب تعديل الكود** ما استطعت: الهوية والمحتوى والباقات والإعدادات كلها من لوحة
الأدمن، وتعديل الملفات نفسها يُحدث تعارضات دمج عند كل تحديث. إن اضطررت، اجعل
تعديلاتك في فرع منفصل وادمج `main` فيه.

## التنصيب اليدوي (خادم خاص بدل Vercel)

```bash
git clone <رابط الـ fork> && cd elhafazhacademy
cp .env.local.example .env.local     # اضبط DATABASE_URL و AUTH_SECRET و CRON_SECRET
npm ci
npm run build                        # يهيّئ القاعدة ثم يبني
npm start                            # المنفذ 3000
```

ثم `/setup` من المتصفح. وللطوارئ فقط (فقدان الوصول لحساب الإدارة):

```bash
node scripts/seed-admin.mjs owner@academy.com "كلمة-مرور-قوية" "مدير الأكاديمية"
```

بديل بحاويات جاهزة: `docker compose up -d --build` — راجع [DOCKER.md](DOCKER.md).

المهام الدورية على خادم خاص تُجدول بـ cron محلي بدل GitHub Actions:

```
*/5 * * * * curl -sf -H "Authorization: Bearer $CRON_SECRET" https://<نطاقك>/api/cron/tick
```
